# GuardGo Mobile

GuardGo mobile app, built with [Expo](https://expo.dev) and Expo Router.

## Setup

```bash
npm install
```

## Run on Android (development build)

The app runs as a development build, not in Expo Go. The first run builds and installs the app on a connected device or emulator:

```bash
npm run android
```

After that, start the dev server and open the installed app:

```bash
npx expo start
```

Rebuild with `npm run android` only after adding a library with native code or changing native config in `app.json`.

## Release APKs

```bash
npm run test-build      # arm64-v8a only, debug-signed  -> builds/test/release.apk
npm run release-build   # all ABIs, minified, upload-key signed -> builds/production/release.apk
```

`release-build` needs the upload key. Keep the keystore outside the repo and add its details to `~/.gradle/gradle.properties`:

```properties
GUARDGO_UPLOAD_STORE_FILE=C:/path/to/guardgo-upload.jks
GUARDGO_UPLOAD_STORE_PASSWORD=...
GUARDGO_UPLOAD_KEY_ALIAS=guardgo-upload
GUARDGO_UPLOAD_KEY_PASSWORD=...
```

### Windows notes

- Gradle needs a JDK it supports (Java 27 fails with "Unsupported class file major version 71"). `npm run android`, `test-build` and `release-build` use Android Studio's bundled JDK automatically when `JAVA_HOME` isn't set; to use another one, set `JAVA_HOME`.
- The native C++ build can fail with `ninja: error: mkdir(...): No such file or directory` because of the 260-character path limit. Install CMake 3.31+ in the Android SDK and add it to `android/local.properties`:

  ```properties
  cmake.dir=C\:\\Users\\<you>\\AppData\\Local\\Android\\Sdk\\cmake\\3.31.6
  ```

## Styling and themes

Styling uses Tailwind CSS v4 through [Uniwind](https://uniwind.dev): put classes on React Native components with `className`.

- Colours, fonts and the light/dark themes live in `src/global.css`, matching the web client.
- Use the semantic colours so screens follow the theme: `bg-background`, `bg-surface`, `border-border`, `text-content`, `text-content-muted`, `bg-primary`, `text-link`, `bg-danger-soft`, …
- Use `font-sans`, `font-sans-medium`, `font-sans-semibold` and `font-sans-bold` (Inter) instead of `font-medium`/`font-bold`.
- The theme defaults to dark, like the web app. Users can switch Light / Dark / System with `<ThemeSwitcher />`.
- Shared UI is in `src/components/ui/`: `Text`, `Button`, `TextField`, `Badge`, `Screen`.
- After changing theme variables in `global.css`, run `npx uniwind generate-artifacts --css ./src/global.css --dts ./src/uniwind-types.d.ts` if TypeScript complains.

## Project structure

```
src/
├── app/            Routes only (Expo Router: every file is a screen, _layout.tsx defines navigators)
├── components/ui/  Reusable UI (Text, Button, TextField, Badge, Screen, ThemeSwitcher)
├── config/         Build-time environment values (env.ts reads EXPO_PUBLIC_* variables)
├── constants/      Fixed values: timeouts, storage keys, theme defaults, badge keywords
├── hooks/          Shared React hooks
├── lib/            Wrappers around platform libraries (storage)
├── services/       Business logic and server calls
│   ├── api/        HTTP layer: config, errors, transport (http), session tokens, client
│   ├── auth.ts
│   ├── server-config.ts
│   └── theme.ts
├── types/          Shared TypeScript types (API, auth, theme, server config, UI)
├── utils/          Pure helper functions (JWT, server URL, badge matching)
└── global.css      Tailwind theme (colours, fonts, light/dark)
```

- Import the HTTP layer from `@/services/api`, not from the files inside it.
- Shared and API types go in `src/types/`. Component prop types (`ButtonProps`, …) stay next to their component.
- `assets/` holds the app icon, splash and other images.

`android/` and `ios/` are generated by `npx expo prebuild` and are not committed.
